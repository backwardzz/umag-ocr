# Накладные → UMAG

Веб-приложение: фото бумажной накладной → распознавание (OCR) → проверка → Excel для импорта в UMAG («Приёмка» → «📥 Импорт товаров»).

- Работает целиком в браузере: фото никуда не отправляются, без ИИ и без платных API.
- Движок OCR — Tesseract (rus + eng), встроен в приложение и после первой загрузки работает без интернета.
- Каждая строка проверяется арифметикой (кол-во × цена = сумма, НДС 16 %), вся накладная — сверкой с «Итого». Если OCR ошибся в цифре, программа исправит её по арифметике или подсветит строку.

## Запуск

Нужен Node.js 18 или 20+.

```bash
npm install        # зависимости + движок OCR и модели rus/eng (~6 МБ) в public/tesseract
npm run dev        # http://localhost:5178
```

Сборка для размещения на любом статическом хостинге (GitHub Pages, Netlify, свой сервер):

```bash
npm run build      # результат в dist/
npm run preview    # проверить сборку локально
```

Сборку нужно открывать по http(s), а не двойным кликом по `index.html`: браузер не запускает воркеры OCR из `file://`. Если приложение открыто по http, а не по https или localhost, камера телефона и копирование в буфер могут не работать.

## Как пользоваться

1. «Выбрать файлы» или «Сфотографировать» (с телефона). Можно сразу несколько накладных.
2. Дождаться распознавания: примерно 30–60 секунд на фото на компьютере, на телефоне дольше.
3. Проверить строки:
   - зелёная галочка — всё сходится;
   - жёлтая — значения восстановлены по арифметике, сверьте с фото;
   - красная — не хватает данных;
   - значок штрихкода — нужно ввести штрихкод.

   Вверху видно, сходится ли сумма строк с «Итого» накладной.
4. «Excel для UMAG» скачивает файл, «Копировать» кладёт столбцы в буфер обмена.

### Загрузка в UMAG

1. «Закупки» → «Приёмка» → новая приёмка, выбрать поставщика и дату.
2. «📥 Импорт товаров» → «Загрузить файл». Второй вариант — кликнуть в окно и нажать Ctrl+V; на вопрос о разделителе выбрать «Табуляция».
3. Над столбцами выбрать их назначение в том же порядке, что в настройках файла. По умолчанию это **Штрихкод, Количество, Цена**. «Продолжить» → проверить → «Провести».

Порядок и набор столбцов, строка заголовка и режим упаковок («3 X 24» — 72 шт или 3 уп) меняются в «Настройках». Цена в файле — за единицу, **с НДС**.

> Публичного шаблона импорта у UMAG нет. Формат взят из их базы знаний (окно «Новый импорт товаров»: вставка столбцов или файл, назначение столбцов выбирается вручную). При первом импорте проверьте, как UMAG назвал столбцы в выпадающих списках, и при необходимости поменяйте порядок в настройках.

### Поставщики без штрихкодов в накладной

У Мегаполиса и Сэт Колы в накладной свои коды товаров, а UMAG ищет товар по штрихкоду:

- Для каждого нового кода штрихкод вводится **один раз** и запоминается в справочнике («Справочник» в шапке). В следующих накладных он подставится сам. После Enter курсор переходит к следующей пустой строке, поэтому удобно сканировать товары USB-сканером подряд.
- **Каталог UMAG**: «Настройки» → «Каталог UMAG» → загрузить выгрузку «Товары → Импорт/Экспорт → Экспорт товаров». Появятся подсказки штрихкода по названию, а для товаров, которых нет в UMAG, — предупреждение.
- Справочник хранится в браузере. Кнопка «Сохранить в файл» делает резервную копию или переносит справочник на другой компьютер.

## Какие накладные понимает

| Поставщик | Формат | Коды |
|---|---|---|
| ТОО «GRAND Кондитер» | З-2, названия в 2 строки | EAN-13 (проверяется контрольная цифра) |
| ТОО «ТК «Мегаполис-Казахстан» | З-2, матричная печать | 8-значные коды поставщика |
| ТОО «Сэт Кола» (Coca-Cola) | свой формат, количество «N X M» | 6-значные коды поставщика |
| Любой другой | форма З-2 («Накладная на отпуск запасов на сторону») | EAN или коды — определяется автоматически |

Поставщик определяется по БИН в накладной (надёжнее всего), потом по названию.

### Добавить поставщика

- **Накладная по форме З-2** — достаточно добавить запись в [src/core/suppliers.ts](src/core/suppliers.ts): БИН, название, тип кодов (`ean` или `digits` + длина) и куда переносится длинное название (`up` — первая часть выше строки с кодом, `down` — хвост ниже).
- **Свой формат** — новый парсер в `src/core/formats/` по образцу [setkola.ts](src/core/formats/setkola.ts) и ветка в [parse.ts](src/core/parse.ts).

Затем положите фото в `samples/`, выполните `npm run ocr -- samples/фото.jpg`, создайте `samples/фото.expected.json` с правильными значениями, и `npm test` будет проверять этот формат.

## Как это устроено

```
фото ─► предобработка (src/core/image.ts, в Web Worker)
         • серое по балансу белого бумаги, синие/красные чернила (печати, подписи, галочки) убираются
         • маска листа — фон вокруг не мешает
         • локальный порог Sauvola — тени и неравномерный свет
         • масштаб по высоте символа, выравнивание перекоса по полосам (частично компенсирует перспективу)
         • удаление линий таблицы
     ─► OCR, проход 1: вся страница (Tesseract, PSM 6)
     ─► определение поставщика/формата, поиск строк таблицы по столбцу кодов
     ─► OCR, проход 2: каждый столбец чисел отдельно, фильтр «только цифры»
     ─► разбор (src/core/formats/*), сверка строк по арифметике (src/core/reconcile.ts),
         сверка с «Итого», при расхождении — подбор по альтернативным прочтениям
     ─► таблица для проверки ─► Excel / буфер обмена (src/core/export.ts)
```

Весь разбор — чистый TypeScript без DOM, поэтому одинаково работает в браузере и в Node (скрипты и тесты).

## Разработка и тесты

```bash
npm test                              # парсеры и Excel на сохранённых результатах OCR (samples/*.ocr.json), быстро
npm run ocr -- samples/1.jpg --text   # полный конвейер в Node: картинка после обработки в out/, результат в samples/1.ocr.json
```

- `http://localhost:5178/?demo=1,2,3` (только `npm run dev`) — сразу загружает `samples/1.jpg`, `2.jpg`, `3.jpg`.
- В dev-режиме результат OCR из браузера лежит в `globalThis.__ocrPages`. Сохранить его как тестовый пример: `fetch('/__save-ocr?name=1-browser', {method:'POST', body: JSON.stringify(__ocrPages[0])})`. Tesseract в браузере и в Node даёт немного разный текст, поэтому полезно тестировать оба варианта.
- `samples/` в `.gitignore`: там реальные накладные с БИН и суммами.

## Ограничения

- Качество зависит от фото. Лучше всего: лист целиком, сверху, ровный свет, оригинал фото (мессенджеры сильно сжимают).
- Наименования OCR читает с ошибками (например, «8шт» → «Вшт»). Для импорта это не важно: UMAG сопоставляет товар по штрихкоду.
- Протестировано на трёх ваших накладных (58 строк, два варианта OCR — Node и браузер, все значения совпадают с эталоном). Новые поставщики и форматы могут потребовать донастройки: присылайте фото.
- ИИ пока не используется. Для неизвестных форматов можно позже добавить необязательное распознавание через модель с поддержкой изображений (например, Claude API). Нынешняя проверка арифметикой и итогом подойдёт и для неё.
