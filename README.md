# Накладные в Sauda

Веб-приложение: фото бумажной накладной → распознавание (OCR) → проверка → приёмка в [Sauda](https://github.com/backwardzz/sauda) одной кнопкой. Те же строки можно скачать файлом Excel или скопировать.

- Работает целиком в браузере: фото никуда не отправляются, без ИИ и без платных API.
- Движок OCR — Tesseract (rus + eng), встроен в приложение и после первой загрузки работает без интернета.
- Каждая строка проверяется арифметикой (кол-во × цена = сумма, НДС 16 %), вся накладная — сверкой с «Итого». Если OCR ошибся в цифре, программа исправит её по арифметике или подсветит строку.

## Запуск

Нужен Node.js 18 или 20+.

```bash
npm install        # зависимости + движок OCR и модели rus/eng (~6 МБ) в public/tesseract
npm run dev        # http://localhost:5178
```

Сборка для размещения на любом статическом хостинге (GitHub Pages, Netlify, свой сервер):

```bash
npm run build      # результат в dist/
npm run preview    # проверить сборку локально
```

Сборку нужно открывать по http(s), а не двойным кликом по `index.html`: браузер не запускает воркеры OCR из `file://`. Если приложение открыто по http, а не по https или localhost, камера телефона и копирование в буфер могут не работать.

## Как пользоваться

1. «Выбрать файлы» или «Сфотографировать» (с телефона). Можно сразу несколько накладных. Принимаются фото (JPG, PNG) и **PDF**: PDF раскладывается на страницы, каждая распознаётся как фото, страницы одной накладной склеиваются. Скан в PDF берётся в родном разрешении картинки, выгрузка из учётной программы рисуется в полном размере (до 30 страниц в файле).
2. Дождаться распознавания: примерно 30–60 секунд на фото на компьютере, на телефоне дольше. Если загрузили не то фото — крестик на его карточке отменяет распознавание и убирает фото, остальные продолжают распознаваться.
3. Проверить строки:
   - зелёная галочка — всё сходится;
   - жёлтая — значения восстановлены по арифметике, сверьте с фото;
   - красная — не хватает данных;
   - жёлтую строку, сверенную с накладной, можно отметить кнопкой «верно» — предупреждение снимется и строка станет обычной; «Всё верно» над таблицей снимает предупреждения сразу со всех жёлтых строк. Ошибки (красные) так снять нельзя. Отметку можно вернуть: «верно · вернуть замечания»;
   - значок штрихкода — нужно ввести штрихкод.

   Вверху видно, сходится ли сумма строк с «Итого» накладной.
4. «В Sauda» открывает сайт Sauda на странице «Накладная из фото»: там видно, какие товары нашлись в базе по штрихкоду, а какие будут созданы, и одной кнопкой создаётся черновик приёмки с поставщиком, количеством и закупочными ценами. Остатки меняются только после «Провести» в Sauda. Строки накладной передаются в адресе страницы и на сервер не уходят.
5. «Excel» скачивает файл, «Копировать» кладёт столбцы в буфер обмена.

### Блоки, пачки и массовые правки

- **1 блок = 10 шт.** Строки сигарет с единицей «блок» при загрузке пересчитываются так, как их принимает Sauda: количество × 10, цена ÷ 10, единица «шт» (1 блок по 11 618 ₸ → 10 шт по 1 161,80 ₸). Сумма остаётся как в накладной. Под количеством и ценой серым видно, как было в накладной («было 1 блок», «было 11 618,00»). Правила пересчёта задаются в «Настройках» → «Пересчёт единиц»: можно поменять множитель или добавить свои правила (например, «1 кор = 12 бут»). Кнопка «Применить к открытым накладным» пересчитывает уже загруженные.
- **Массовые правки** — панель над таблицей:
  - выбор строк: «все», по единице («блок · 11», «без ед. · 5») или галочками, диапазон — галочка с Shift;
  - действия применяются к выбранным строкам, а если ничего не выбрано — ко всем: количество или цена × / ÷ N, новая единица, пресеты из правил («1 блок → 10 шт»), «Как в накладной» (вернуть количество, единицу и цену);
  - «Отменить» откатывает последнее массовое действие;
  - сумма при массовых правках не меняется — это деньги по накладной.
- В поле количества или цены можно набрать `*10` или `/10` — значение умножится или разделится, сумма останется прежней.

### Файл Excel

По умолчанию столбцы в файле и в буфере обмена: **Штрихкод, Количество, Название, Ед. изм, Цена приходная**. Порядок и набор столбцов (можно добавить сумму, код поставщика или убрать цену), строка заголовка и режим упаковок («3 X 24» — 72 шт или 3 уп) меняются в «Настройках». Цена приходная в файле — за единицу, **с НДС**, после пересчёта единиц (блок → 10 шт: цена за пачку). Единица измерения берётся из накладной и правится в таблице; в режиме упаковок выгружается «уп».

### Поставщики без штрихкодов в накладной

У Мегаполиса, Сэт Колы, Евразиан и ИП Искандыров в накладной свои коды товаров, у MAYAN и Карлсберг Пепси кодов нет вовсе, а Sauda ищет товар по штрихкоду:

- Для каждого нового кода штрихкод вводится **один раз** и запоминается в справочнике («Справочник» в шапке). В следующих накладных он подставится сам. Если кода нет, штрихкод запоминается по названию; OCR читает название каждый раз чуть по-разному, поэтому подходит и похожее название — такая строка помечается «сверьте». После Enter курсор переходит к следующей пустой строке, поэтому удобно сканировать товары USB-сканером подряд.
- **Каталог Sauda и автозаполнение**: «Настройки» → «Каталог Sauda» → загрузить выгрузку «Товары → Импорт/Экспорт → Экспорт товаров» (один раз; хранится только в этом браузере — сайт публичный, поэтому каталог в код не встроен). После этого штрихкоды, которых нет ни в накладной, ни в справочнике, **заполняются автоматически**:
  - по NTIN из накладной (Евразиан: часть товаров заведена в Sauda со штрихкодом = NTIN или с NTIN в «Доп. коде»);
  - по похожему названию с учётом объёма и веса («0.45» = «450мл», «380гр» = «0,38 кг»), единицы и поставщика. Если два товара каталога почти одинаково похожи, штрихкод не подставляется — остаются подсказки в выпадающем списке.

  Такие строки жёлтые, с пометкой «автозаполнение · возможна ошибка» и названием найденного товара, под таблицей — сколько строк заполнено так. Кнопка «верно» запоминает штрихкод в справочнике, в следующий раз он подставится без пометки. На сохранённых накладных автозаполнение по названию выбирает верный товар примерно в 9 случаях из 10 (`npm run catalog`); ошибки — почти одинаковые товары («вода газ» / «не газ», когда OCR потерял «без»). Для товаров, которых нет в каталоге (например, Pepsi 0,45 ж/б), ничего не подставляется.
- Также каталог даёт подсказки штрихкода по названию, а для товаров, которых нет в Sauda, — предупреждение.
- **Доп. код → основной штрихкод.** Если штрихкод строки (из накладной, справочника или введённый вручную) записан в каталоге Sauda у товара в столбце «Доп. код» (колонка D выгрузки), он заменяется основным штрихкодом товара из столбца «Штрихкод» (колонка B). Под штрихкодом видно, что было в накладной: «доп. код 4870132003721 → основной». Если каталог очистить, вернётся штрихкод из накладной.
- **Вкусы одного товара складываются.** В базе Sauda вкусы часто заведены одним товаром с дополнительными штрихкодами (Borjomi Energy, йогурты Campina). После замены у таких строк один и тот же основной штрихкод, и в файле для Sauda они складываются в одну. Разные товары Sauda с одинаковым названием («Мармелад Strike 70г» по 129 и по 153 ₸) не складываются.
- **Единица из каталога.** Если единица в накладной не прочиталась, берётся единица товара в Sauda.
- **Исправление штрихкодов по каталогу.** В мелком шрифте OCR путает 5, 6, 8 и 9. Если у штрихкода из накладной не сходится контрольная цифра и его нет в каталоге, программа ищет в каталоге товар, чей штрихкод отличается одной цифрой, или похожий по названию, у которого отличаются не больше трёх цифр. Исправляет, только если такой кандидат один; строка жёлтая, в замечании видно, как штрихкод был прочитан. Штрихкод с верной контрольной цифрой не трогается, даже если его нет в каталоге: это может быть новый товар, а у соседних вкусов одной марки штрихкоды отличаются в 1–2 цифрах.
- **Новая строка по названию.** Если добавить строку («Добавить строку») и ввести название, товар ищется в каталоге Sauda, и в строке сразу появляются его штрихкод, название и единица. Строка помечается «автозаполнение»; кнопка «верно» подтверждает штрихкод. То же происходит, если исправить название у строки накладной, для которой штрихкод не найден.
- **Названия из каталога.** Если штрихкод строки есть в каталоге, название заменяется названием из Sauda, и в файл попадёт именно оно. Штрихкод может быть взят из накладной, из справочника, подобран автоматически или введён вручную. Для строк без штрихкода порядок такой: штрихкод подбирается по названию из накладной, затем название меняется на каталожное. Название из накладной сохраняется: оно видно под строкой серым («в накладной: …») и в отчёте, по нему же идут поиск в каталоге и справочник. Название, исправленное вручную, больше не заменяется, пока не поменяется штрихкод. Если каталог очистить, вернутся названия из накладной. Проверка: `npx tsx scripts/test-catalog-names.ts` (входит в `npm test`).
- **Ошибка в одной цифре кода.** У кодов поставщика нет контрольной цифры, и OCR иногда читает «13730» вместо «73730». Если в справочнике у этого поставщика ровно один код отличается одной цифрой и название похоже, подставляется его штрихкод, строка жёлтая с пометкой «сверьте».
- Справочник хранится в браузере. Кнопка «Сохранить в файл» делает резервную копию или переносит справочник на другой компьютер.

Если столбец «Сумма» на фото не прочитан (обрезан или в тени), а под таблицей есть «Итого», количество и цена определяются по нему: сумма произведений по строкам должна совпасть с итогом.

Поставщик определяется по БИН в накладной (надёжнее всего), потом по названию. Тот же список виден в приложении: на стартовой странице («Какие накладные принимает система») и в окне «Как загрузить в Sauda»; он строится из [src/core/suppliers.ts](src/core/suppliers.ts), поэтому новому поставщику достаточно заполнить поле `goods`.

Накладная из одной строки тоже разбирается. Если столбец «Сумма» на фото не прочитан (обрезан, в тени), сумма строки считается как количество × цена и сверяется с итогом. Цена или итог без запятой (в 100 раз больше, чем у соседних строк) исправляются с пометкой. Пунктирные линии таблицы убираются при обработке фото.

Столбцы количества, цены, суммы и НДС находятся по арифметике (количество × цена = сумма в большинстве строк), поэтому лишние столбцы — коробки, цена по прайсу, скидка, вес — не мешают.

### Несколько страниц, повторы, бонусы

- **Накладная на нескольких листах** (Евразиан): загрузите все фото — страница с тем же поставщиком и номером присоединится к первой, в таблице будут все строки, а «Итого» сверится по всей накладной. Фото страниц переключаются над картинкой («Стр. 1», «Стр. 2»).
- **Та же накладная второй раз** (то же фото или повторный снимок): карточка помечается «Повтор», чтобы не провести приёмку дважды.
- **Одинаковый штрихкод в двух строках** (бонус «БОНУС! … 1,00 ₸» у БЕС БАТЫР): в файле для Sauda строки складываются в одну — количество суммируется, цена средняя. В таблице такая строка помечена «сложится со строкой N».

### Добавить поставщика

- **Накладная по форме З-2** — достаточно добавить запись в [src/core/suppliers.ts](src/core/suppliers.ts): БИН, название, тип кодов (`ean` или `digits` + длина) и куда переносится длинное название (`up` — первая часть выше строки с кодом, `down` — хвост ниже).
- **Свой формат** — новый парсер в `src/core/formats/` по образцу [setkola.ts](src/core/formats/setkola.ts) и ветка в [parse.ts](src/core/parse.ts).

Затем положите фото в `samples/`, выполните `npm run ocr -- samples/фото.jpg`, создайте `samples/фото.expected.json` с правильными значениями, и `npm test` будет проверять этот формат.

## Как это устроено

```
фото ─► предобработка (src/core/image.ts, в Web Worker)
         • серое по балансу белого бумаги, синие/красные чернила (печати, подписи, галочки) убираются
         • маска листа — фон вокруг не мешает
         • локальный порог Sauvola — тени и неравномерный свет
         • масштаб по высоте символа, выравнивание перекоса по полосам (частично компенсирует перспективу)
         • удаление линий таблицы
     ─► OCR, проход 1: вся страница (Tesseract, PSM 6)
     ─► определение поставщика/формата, поиск строк таблицы по столбцу кодов
     ─► OCR, проход 2: каждый столбец чисел отдельно, фильтр «только цифры»
     ─► разбор (src/core/formats/*), сверка строк по арифметике (src/core/reconcile.ts),
         сверка с «Итого», при расхождении — подбор по альтернативным прочтениям
     ─► таблица для проверки ─► Excel / буфер обмена (src/core/export.ts)
```

Весь разбор — чистый TypeScript без DOM, поэтому одинаково работает в браузере и в Node (скрипты и тесты).

- `samples/` в `.gitignore`: там реальные накладные с БИН и суммами.

## Ограничения

- Качество зависит от фото. Лучше всего: лист целиком, сверху, ровный свет, оригинал фото (мессенджеры сильно сжимают).
- Наименования OCR читает с ошибками (например, «8шт» → «Вшт»). Для импорта это не важно: Sauda сопоставляет товар по штрихкоду.
- Протестировано на накладных 18 поставщиков (24 эталона в `samples/`: 336 строк, все количества, цены, суммы, штрихкоды и единицы совпадают с эталоном). Фото с EXIF-поворотом (вертикальные снимки с телефона) в браузере поворачиваются сами, `npm run ocr` тоже учитывает EXIF. Новые поставщики и форматы могут потребовать донастройки: присылайте фото.
- Шапку (номер и дату) OCR читает хуже таблицы: цифра может быть прочитана неверно — поправьте в полях над таблицей. Если лист обрезан на фото (столбец сумм у края), сумма строки считается как количество × цену.
- ИИ пока не используется. Для неизвестных форматов можно позже добавить необязательное распознавание через модель с поддержкой изображений (например, Claude API). Нынешняя проверка арифметикой и итогом подойдёт и для неё.
